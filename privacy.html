Privacy information.

What the current CloudLatch implementation handles, where it is stored and when it reaches AWS.

Last reviewed: October 26, 2026

Development-stage notice

This describes the inspected development implementation. It is not the final App Store privacy policy or disclosure. Release-artifact verification, retention and removal instructions, and a dedicated privacy contact must be finalized before distribution.

Credentials and authentication

CloudLatch reads source IAM user access keys from the AWS configuration directory you select. It uses them to sign AWS Security Token Service (STS) requests. An MFA code and device serial are supplied to AWS to request a temporary source session.

Temporary source credentials are held in memory and stored in macOS Keychain. The MFA serial is also stored in Keychain. CloudLatch uses the source session to sign requests to assume your configured roles.

Role ARNs and a role-session name containing the configured alias are sent to AWS. Temporary role credentials returned by AWS are written to the selected role profile and default in your chosen credentials file.

Local configuration and diagnostics

CloudLatch stores role aliases, role ARNs and preferences locally in Application Support. It stores a bookmark for access to the selected directory. Local session state includes profile, account, expiry and error state.

Local diagnostics record generic refresh events in Application Support and macOS logging. The inspected implementation omits profile/source names and raw AWS error payloads from diagnostic events. Local files and configuration remain until removed; uninstalling the app alone is not a verified complete-erasure process.

AWS processing and SDK metadata

Authentication communicates directly with AWS through the AWS SDK for Swift. Requests can include protocol and diagnostic metadata such as SDK and operating-system versions and the application identifier. The SDK declares diagnostic-data processing for app functionality.

Disabling SDK client logging does not mean that no data is transmitted. AWS processing and retention are governed by the applicable AWS terms and privacy information; CloudLatch does not control AWS-side retention.

No app-owned analytics, advertising, crash-reporting service or backend was identified in the inspected implementation. This statement must be rechecked against the distribution artifact and does not replace third-party disclosures.

Retention and removal

Temporary AWS credentials expire according to the AWS response. Local configuration, access bookmarks, state and diagnostic files can persist separately from that expiry. Changing authentication settings invalidates the cached source session.

Complete removal steps, including Keychain entries and credentials written to shared AWS files, are still being verified for the release. Do not assume that deleting the app removes those entries or revokes credentials at AWS.

This website and support

These pages contain no analytics scripts, advertising, cookies, embedded third-party media or remote fonts. A hosting provider may process connection information when serving them.

Support links lead to GitHub. GitHub processes information under its own policies, and public issues and attachments are visible to everyone. Avoid personal data and AWS identifiers in reports.

Contact

The current project contact is GitHub support. For a privacy question requiring personal information, request a private contact channel without posting the information publicly. Suspected security vulnerabilities belong in private vulnerability reporting.

A dedicated privacy contact and the final release policy remain prerequisites for distribution.

CloudLatch is independent software, not affiliated with Amazon Web Services.
